# Keymaps

A complete reference of every keymap Mars binds. Generated by reading each
`vim.keymap.set` call site directly (110 call sites across 16 files as of
this writing), cross-referenced against the which-key group labels in
[`lua/mars/plugins/which-key.lua`](lua/mars/plugins/which-key.lua), so this
document tracks the actual bindings rather than a paraphrase of them. If a
keymap changes, this file can drift; when in doubt, `grep -rn
"vim.keymap.set" lua/` is the source of truth, not this table.

`<leader>` is `<Space>` (see `init.lua`). Where a row lists more than one
key, they're aliases for the same action (e.g. a `<leader>` mnemonic plus an
F-key), not separate bindings with different behavior.

## Debug (`<leader>d`)

Source: [`lua/mars/core/dap.lua`](lua/mars/core/dap.lua). Every action is
bound to a `<leader>d*` mnemonic, and the core stepping/breakpoint set is
also bound to one or more F-key forms, mirroring xterm/tmux's convention of
sending Shift/Ctrl-Fn as an extended F-number (e.g. Shift-F5 arrives as
`<F17>`) rather than `<S-F5>` directly: both forms are bound so whichever a
given terminal reports still fires. All calls are pcall-guarded against
nvim-dap/nvim-dap-ui not being loaded yet.

| Key(s)                          | Mode | Action                              |
| ---------------------------------- | ---- | -------------------------------------- |
| `<leader>db`, `<F9>`               | n    | Toggle breakpoint                    |
| `<leader>dB`, `<F21>`, `<S-F9>`     | n    | Set a conditional breakpoint (prompts for the condition) |
| `<leader>dc`, `<F5>`               | n    | Continue                             |
| `<leader>dC`, `<F17>`, `<S-F5>`     | n    | Run to cursor                        |
| `<leader>di`, `<F11>`              | n    | Step into                            |
| `<leader>do`, `<F23>`, `<S-F11>`    | n    | Step out                             |
| `<leader>dO`, `<F10>`              | n    | Step over                            |
| `<leader>dj`, `<F6>`               | n    | Move down a stack frame              |
| `<leader>dk`, `<F18>`, `<S-F6>`     | n    | Move up a stack frame                |
| `<leader>dl`, `<F29>`, `<C-F5>`     | n    | Run last debug configuration again   |
| `<leader>dP`, `<F7>`               | n    | Pause                                |
| `<leader>dt`, `<F8>`               | n    | Terminate: closes dap-ui, then terminates the DAP session |
| `<leader>de`, `<F12>`              | n    | dap-ui: evaluate expression under cursor |
| `<leader>da`                       | n    | Continue, after prompting for launch arguments |
| `<leader>dr`                       | n    | Toggle the REPL window               |
| `<leader>ds`                       | n    | Session (nvim-dap's `dap.session()`) |
| `<leader>du`                       | n    | dap-ui: manual toggle (separate from the automatic show/hide on session start/end) |
| `<leader>dw`                       | n    | Widget hover: debug info for the expression under the cursor |

### Hunk (`<leader>gh`)

A which-key sub-group registered dynamically inside `gitsigns.lua` (not in

once gitsigns is loaded.

| Key            | Mode | Action                                                  |
| -------------- | ---- | ---------------------------------------------------------- |
| `<leader>ghs`  | n, x | Stage hunk (staging an already-staged hunk unstages it; gitsigns' own toggle behavior); visual mode stages the hunks spanning the selected line range |
| `<leader>ghr`  | n, x | Reset (discard) hunk; visual mode resets the hunks spanning the selected line range |
| `<leader>ghS`  | n    | Stage the entire buffer                                 |
| `<leader>ghR`  | n    | Reset the entire buffer                                 |
| `<leader>ghp`  | n    | Preview hunk in a floating window                       |
| `<leader>ghb`  | n    | Blame current line (full, floating)                     |
| `<leader>ghB`  | n    | Toggle current-line blame (virtual text)                |
| `<leader>ghd`  | n    | Diff current buffer against the index                   |

See also `]h` / `[h` for hunk navigation, in

## OpenCode (`<leader>o`)

Source: [`lua/mars/plugins/opencode.lua`](lua/mars/plugins/opencode.lua).
The sole AI surface in this config (see AGENTS.md). `ask(...)` variants open
an editable prompt pre-filled with a context placeholder; `prompt(...)`
variants submit immediately against `@this` (the current selection, or the
cursor position with no selection). The terminal runs through the shared
terminal manager (see [Terminal](#terminal-leadert)) in a right split:
submitting a prompt brings it into view.

| Key           | Mode | Action                                     |
| ------------- | ---- | --------------------------------------------- |
| `<leader>oa`  | n, x | Ask (`@this`)                                |
| `<leader>ob`  | n, x | Ask, scoped to `@buffer`                      |
| `<leader>oB`  | n, x | Ask, scoped to `@buffers` (all open buffers)  |
| `<leader>od`  | n, x | Ask, scoped to `@diagnostics`                 |
| `<leader>om`  | n, x | Ask, scoped to `@marks`                       |
| `<leader>ov`  | n, x | Ask, scoped to `@visible` (visible text)      |
| `<leader>ox`  | n, x | Ask, scoped to `@quickfix`                    |
| `<leader>oi`  | n, x | Ask with an empty prompt                      |
| `<leader>of`  | n, x | Fix `@this` immediately                       |
| `<leader>oe`  | n, x | Explain `@this` immediately                   |
| `<leader>or`  | n, x | Review `@this` immediately                    |
| `<leader>oo`  | n, x | Optimize `@this` immediately                  |
| `<leader>os`  | n, x | Write a test for `@this` immediately          |
| `<leader>oD`  | n, x | Diagnose `@this` immediately                  |
| `<leader>og`  | n, x | Add range as context (operator-pending expr mapping) |
| `<leader>ol`  | n    | Add current line as context (operator-pending expr mapping) |
| `<leader>on`  | n    | Start a new session                           |
| `<leader>oc`  | n    | Close session (closes the OpenCode terminal: there's no separate server-side "close session" command) |
| `<leader>ot`  | n    | Toggle the OpenCode terminal (right split)    |
| `<leader>oq`  | n    | Stop/close the OpenCode terminal (same underlying action as `<leader>oc`, kept as a separate mnemonic) |
| `<leader>oX`  | n, x | Open the action/prompt picker                 |
| `<leader>ou`  | n    | Scroll session pane up half a page            |
| `<leader>oj`  | n    | Scroll session pane down half a page          |

`<leader>oc` and `<leader>oq` both call the exact same `close()` function;
not a documentation slip, the file's own header comment explains the
duplication is intentional (two mnemonics for one action, left over from
when `session.close` was still a distinct server command).

See also `go` / `goo` in [Ungrouped / raw keymaps](#ungrouped--raw-keymaps)
Non-`<leader>` mirrors of `<leader>og` / `<leader>ol`, matching
opencode.nvim's own suggested keymaps.

## Terminal (`<leader>t`)

Source: [`lua/mars/core/terminal.lua`](lua/mars/core/terminal.lua). Generic
shell terminals (`vim.o.shell`) running through the shared terminal manager.
`tt` toggles a horizontal split across the bottom (40% height by default);
`tv` toggles a vertical split down the right (40% width by default): each an
independent terminal. Sizes are configurable via
`vim.g.mars_split_terminal_size` (e.g. `{ height = 0.5, width = 0.45 }`), set
in `lua/mars/local.lua`. A count opens another stacked terminal
(`2<leader>tt`).

The same underlying manager (`lua/mars/helpers/term.lua`) also runs the
lazygit, scooter, and OpenCode terminals, so they share one behavior contract:
entering a terminal window drops straight into terminal mode, double-`<Esc>`
returns to normal mode (single `<Esc>` still reaches the TUI), `q` in normal
mode inside a terminal closes it (terminating the job), and `<C-h/j/k/l>`
from inside a terminal navigate to the adjacent split.

| Key           | Mode | Action                             |
| ------------- | ---- | ------------------------------------- |
| `<leader>tt`  | n    | Toggle horizontal terminal (bottom)  |
| `<leader>tv`  | n    | Toggle vertical terminal (right)     |

Also available as `:MarsTerminal` (the horizontal terminal).

## Copy & Paste (`<leader>y`)

Source: [`lua/mars/core/clipboard.lua`](lua/mars/core/clipboard.lua) and
[`lua/mars/plugins/fzf-lua.lua`](lua/mars/plugins/fzf-lua.lua). Mars
sets `clipboard = ""` (not `unnamedplus`) in `core/options.lua`, so plain
`y`/`p`/`d` never silently touch the system clipboard: these are the
explicit, opt-in path to the `"+` register. `<leader>Y` and `<leader>p` sit
in [Ungrouped / raw keymaps](#ungrouped--raw-keymaps): capital `Y` is a
separate top-level key, and `p` isn't under the `y` prefix.

| Key           | Mode    | Action                                    |
| ------------- | ------- | --------------------------------------------- |
| `<leader>y`   | n       | Yank the current line to the system clipboard |
| `<leader>y`   | v, x    | Yank the selection to the system clipboard    |

## Reserved, unused groups

Two which-key groups are registered in
[`lua/mars/plugins/which-key.lua`](lua/mars/plugins/which-key.lua) but have
**no keymaps bound under them anywhere in the codebase** today (confirmed by
grepping every `vim.keymap.set` call site, not just guessed at):

- **`<leader>a`: "AI"**. Reserved namespace; not wired to anything yet.
  `README.md`'s keymap-namespace table lists it as "AI (opencode)", but the
  actual OpenCode integration lives entirely under `<leader>o` (see
  [OpenCode](#opencode-leadero) above): `<leader>a` itself is untouched.

Pressing `<leader>a` shows an empty which-key popup: this is expected, not
a bug, and is called out in `which-key.lua`'s own comments.

## Ungrouped / raw keymaps

Keymaps that either aren't `<leader>`-prefixed, or are `<leader>`-prefixed
but don't fall under one of the which-key groups above (a different case, or
a key that which-key doesn't nest under any registered group). Organized by
file/feature.

### Clipboard (`lua/mars/core/clipboard.lua`)

| Key           | Mode    | Action                                                      |
| ------------- | ------- | ---------------------------------------------------------------- |
| `<leader>Y`   | n       | Yank to end of line, to the system clipboard (`"+y$`)            |
| `<leader>p`   | n       | Paste from the system clipboard                                  |
| `<leader>p`   | v, x    | Paste from the system clipboard, replacing the selection (deletes selection into the black-hole register first, so the unnamed register isn't clobbered) |
| `<leader>R`   | n       | Replace every buffer-wide occurrence of the word under the cursor (prompts for replacement, then a confirm-each `:s///gc`) |
| `<leader>R`   | x       | Replace every buffer-wide occurrence of the visual selection's text (same confirm-each substitution) |

### Insert-mode edits & accents (`lua/mars/core/insert.lua`)

A Spanish/Catalan accent input layer built on Neovim's own digraphs
(`:help digraphs`, `:help i_CTRL-K`) instead of a system keyboard-layout
switch. `<A-'>`/`` <A-`> ``/`<A-;>` leave the digraph prompt open; the next
key typed (a vowel) completes the pair.

| Key           | Mode | Action                                            |
| ------------- | ---- | ------------------------------------------------------ |
| `;;`          | n, i | Append `;` at end of line (unless already there), then insert mode |
| `<A-e>`       | i    | Insert `€`                                              |
| `<A-'>`       | i    | Acute accent, then a vowel (á é í ó ú)                  |
| `` <A-`> ``   | i    | Grave accent, then a vowel (à è ò)                      |
| `<A-;>`       | i    | Diaeresis, then a vowel (ü)                             |
| `<A-n>`       | i    | Insert `ñ`                                              |
| `<A-N>`       | i    | Insert `Ñ`                                              |
| `<A-c>`       | i    | Insert `ç`                                              |
| `<A-C>`       | i    | Insert `Ç`                                              |
| `<A-1>`       | i    | Insert `¡`                                              |
| `<A-/>`       | i    | Insert `¿`                                              |
| `<A-.>`       | i    | Insert `·` (Catalan `l·l`)                              |
| `<A-h>`       | i    | Move left without breaking the current undo sequence    |
| `<A-l>`       | i    | Move right without breaking the current undo sequence   |
| `<C-h>`       | i    | Backspace, but as its own undo step (starts a new undo sequence first) |

Note: insert-mode `<C-h>` above is unrelated to normal-mode `<C-h>` (split
navigation, below); different modes, no conflict.

### Split navigation & resize (`lua/mars/core/splits.lua`)

| Key                        | Mode | Action                                                          |
| ---------------------------- | ---- | -------------------------------------------------------------------- |
| `<C-h>`                     | n    | Focus the split to the left, wrapping to the rightmost split if already at the left edge |
| `<C-j>`                     | n    | Focus the split below, wrapping to the topmost split if already at the bottom edge |
| `<C-k>`                     | n    | Focus the split above, wrapping to the bottommost split if already at the top edge |
| `<C-l>`                     | n    | Focus the split to the right, wrapping to the leftmost split if already at the right edge |

| Key     | Mode | Action                                                            |

| `<Tab>` | i, s | Jump an active snippet; else expand a matching trigger word; else insert a literal `<Tab>` |

### OpenCode operator mirrors (`lua/mars/plugins/opencode.lua`)

Non-`<leader>` mirrors of `<leader>og`/`<leader>ol` (see

| Key    | Mode | Action                                                    |

### Dashboard (`lua/mars/ui/dashboard.lua`)

Buffer-local keymaps, only active while the start-screen dashboard buffer is
current (shown once on a bare, argument-less `VimEnter`). Each action degrades
gracefully (dimmed entry, warning notification) instead of erroring when its
dependency isn't wired up yet. Note: the `vim.keymap.set` calls for these
don't pass an explicit `desc`: the descriptions below come from the
`ACTIONS`/`MAINTENANCE_ACTIONS` table that also drives the rendered menu
text, not from a `desc` field on the keymap itself.

| Key | Mode | Action                                              |
| --- | ---- | ---------------------------------------------------- |
| `f` | n    | Find File (fzf-lua, if installed)                  |
| `g` | n    | Find Text / live grep (fzf-lua, if installed)      |
| `r` | n    | Recent Files (fzf-lua oldfiles, if installed)      |
| `s` | n    | Restore Session (if the session module is loaded)  |
| `q` | n    | Quit (`:qa`)                                       |
| `p` | n    | Plugin Status: notify a summary of `vim.pack.get()` |
| `m` | n    | Tool Installer: open `:Mason`, if registered       |
